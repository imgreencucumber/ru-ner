# ru-ner

[![CI](https://github.com/imgreencucumber/ru-ner/actions/workflows/ci.yml/badge.svg)](https://github.com/imgreencucumber/ru-ner/actions/workflows/ci.yml)

NER для русского языка: люди (PER), места (LOC) и организации (ORG).
На одном тесте сравниваю CRF, Natasha, дообученный ruBERT и LLM (GigaChat, YandexGPT) по качеству и скорости.
Лучшая модель квантизована в int8 и работает как сервис на FastAPI на обычном CPU, без PyTorch и GPU.

- Модель на Hugging Face: [imgreencucumber/rubert-ner-collection3](https://huggingface.co/imgreencucumber/rubert-ner-collection3)
- Анализ данных: [notebooks/01_eda.ipynb](notebooks/01_eda.ipynb)
- Разбор ошибок всех моделей: [notebooks/02_error_analysis.ipynb](notebooks/02_error_analysis.ipynb)

## Результаты

Тест Collection3: 1922 предложения, 4001 сущность. F1 на уровне сущностей (`seqeval`): сущность засчитывается,
только если совпали обе границы и тип. В скобках 95% bootstrap-интервал.
«Новые сущности» — те, которых не было в train. WikiNEuRal — другой домен (Википедия), модели на нём не обучались.

| Модель | F1 | Новые сущности | WikiNEuRal | Задержка |
|---|---|---|---|---|
| **ruBERT, ONNX int8** | **0.977** (0.971–0.982) | **0.959** | **0.800** | 16 мс, CPU |
| ruBERT, PyTorch | 0.976 (0.970–0.981) | 0.957 | 0.799 | 13 мс, GTX 1060 |
| Natasha | 0.935 (0.926–0.943) | 0.889 | 0.764 | 2 мс, CPU |
| CRF | 0.901 (0.890–0.911) | 0.818 | 0.563 | 0.4 мс, CPU |
| GigaChat-3-Ultra, 5 примеров в промпте | 0.828 (0.815–0.841) | 0.803 | — | 750 мс, API |
| GigaChat-3-Pro, 5 примеров | 0.743 (0.728–0.760) | 0.694 | — | 490 мс, API |
| YandexGPT Lite, 5 примеров | 0.686 (0.668–0.705) | 0.664 | — | 540 мс, API |
| GigaChat-3-Lightning, 5 примеров | 0.589 (0.573–0.606) | 0.688 | — | 260 мс, API |

Задержка — одно предложение за вызов, медиана. CPU: Intel Core i3-8100, 4 потока. У LLM в задержку входит сеть.
Варианты LLM без примеров, расход токенов и все промежуточные цифры лежат в [results/](results/).

Сервис в Docker (4 ядра, один процесс uvicorn): 26 запросов в секунду и 34 мс в медиане на одиночных запросах,
46 запросов в секунду при 4 одновременных клиентах. Размер образа около 250 МБ в сжатом виде.

## Главное

- **Дообученный ruBERT лучше всех** и по общему F1, и на новых сущностях. Разница с Natasha (+4.1 пункта)
  и с CRF (+7.5) статистически надёжна по парному bootstrap.
- **Квантизация в int8 не стоила качества**: F1 не изменился, модель стала в 4 раза меньше (680 → 170 МБ),
  а одиночный запрос на CPU в 2.3 раза быстрее, чем в PyTorch.
- **LLM в режиме промптинга сильно отстают**: лучшая (GigaChat-3-Ultra) на 15 пунктов хуже ruBERT,
  при этом почти в 50 раз медленнее и требует внешнего API. Главная проблема LLM — пропуски и соглашения разметки:
  например, должности и кавычки в названиях организаций. Хуже всего у LLM с ORG (0.67 у Ultra против 0.94 у ruBERT).
- **YandexGPT отказывается обрабатывать около четверти новостей** из-за модерации («Я не могу обсуждать
  эту тему»), поэтому на политических текстах его нельзя использовать даже при хорошем качестве ответов.
- **CRF сильнее всех опирается на запоминание**: на знакомых сущностях F1 0.961, на новых 0.818,
  на WikiNEuRal 0.563.
- **Часть «ошибок» — это шум разметки.** В 15 случаях, где четыре совершенно разные модели согласны между собой
  и расходятся с эталоном, явной ошибки моделей не нашлось: это пропуски и спорные соглашения в разметке.

## Демо и API

Сервис отдаёт страницу для ручной проверки (`/`), API (`POST /extract`, `POST /extract/batch`)
и документацию (`/docs`).

```bash
docker build -t ru-ner .
docker run -p 8000:8000 ru-ner
```

Страница: http://127.0.0.1:8000. Запрос к API:

```bash
curl -X POST http://127.0.0.1:8000/extract -H "Content-Type: application/json" \
  -d '{"text": "Глава Минфина Антон Силуанов встретился в Москве с представителями МВФ."}'
```

```json
{"entities": [
  {"text": "Минфина", "type": "ORG", "start": 6, "end": 13},
  {"text": "Антон Силуанов", "type": "PER", "start": 14, "end": 28},
  {"text": "Москве", "type": "LOC", "start": 42, "end": 48},
  {"text": "МВФ", "type": "ORG", "start": 67, "end": 70}
]}
```

`start` и `end` — позиции символов во входном тексте. Модель при сборке образа скачивается с Hugging Face,
поэтому образ собирается из чистого репозитория. Деплой в Yandex Cloud Serverless Containers: [deploy/yandex_cloud.md](deploy/yandex_cloud.md).

## Как устроено

1. **Данные.** Collection3 (новости, ручная разметка) для обучения и оценки, тест WikiNEuRal-ru для проверки
   на другом домене. Датасеты скачиваются с HF Hub по зафиксированным ревизиям.
2. **Baseline.** Natasha (готовая библиотека) и CRF с ручными признаками, параметры CRF подобраны на validation.
3. **ruBERT.** `DeepPavlov/rubert-base-cased` + линейный слой, дообучение через Hugging Face `Trainer`,
   выравнивание меток по subword-токенам. При предсказании — декодирование Витерби, которое не допускает
   некорректных BIO-последовательностей (+0.2 пункта F1 к независимому выбору меток, без переобучения).
4. **Оценка.** Bootstrap-интервалы, парный bootstrap для сравнения моделей, метрики на новых и знакомых
   сущностях, тест без предложений, дословно повторяющихся в train, автоматическая классификация ошибок.
5. **ONNX.** Экспорт через `torch.onnx`, оптимизация графа ONNX Runtime, динамическая int8-квантизация.
6. **LLM.** Zero-shot и few-shot промпты, ответ в JSON, сопоставление ответа с позициями в тексте с учётом
   словоформ, кавычек, повторов и выдуманных сущностей. Модели для полного прогона выбирались по пилоту
   на validation, тест для подбора не использовался.
7. **Сервис.** FastAPI + ONNX Runtime без PyTorch, Docker, нагрузочный тест, CI на GitHub Actions.

## Воспроизведение

Нужны [uv](https://docs.astral.sh/uv/) и для обучения видеокарта NVIDIA (на GTX 1060 6GB обучение занимает 11 минут).

```bash
uv sync                                            # все зависимости, включая PyTorch
uv run python scripts/run_baselines.py             # Natasha и CRF
uv run python scripts/train_bert.py                # дообучение ruBERT
uv run python scripts/export_onnx.py               # ONNX + int8
uv run python scripts/evaluate.py                  # интервалы, новые сущности, типы ошибок
uv run python scripts/benchmark.py                 # скорость всех локальных моделей
uv run pytest                                      # тесты
```

LLM-эксперименты требуют ключей API в `.env` (образец в [.env.example](.env.example)):

```bash
uv run python scripts/run_llm.py --model gigachat3_ultra --mode few
```

Сырые ответы LLM сохранены в [results/llm_raw/](results/llm_raw/), поэтому метрики по ним пересчитываются
без повторных платных запросов.

## Структура

```
src/ru_ner/
  data.py            загрузка Collection3 и WikiNEuRal, BIO-разметка
  crf.py             признаки и обучение CRF
  natasha_baseline.py
  bert.py            дообучение ruBERT
  inference.py       инференс без PyTorch: токенизация, ONNX Runtime, Витерби, сырой текст → сущности
  export.py          экспорт в ONNX и квантизация
  evaluation.py      bootstrap, новые сущности, классификация ошибок
  llm.py, llm_ner.py клиенты GigaChat и YandexGPT, промпты, сопоставление ответов с текстом
  service.py         FastAPI
scripts/             запуск экспериментов
notebooks/           EDA и разбор ошибок
results/             метрики, предсказания всех моделей, ответы LLM, замеры скорости
tests/               тесты (модели в них поддельные, ничего не скачивается)
```

## Ограничения

- Модель обучена на новостях 2010-х. На текстах другого стиля качество ниже: на WikiNEuRal F1 0.80.
- Разметка WikiNEuRal автоматическая и содержит класс MISC, которого нет в Collection3, поэтому F1 на нём занижен:
  около половины «лишних» сущностей ruBERT приходится на MISC.
- Скорость измерена на домашнем компьютере, фоновая нагрузка влияет на абсолютные цифры.
  Сравнения внутри одного замера корректны.
- В экспериментах с GigaChat отключена проверка TLS-сертификата: сертификат API выдан корневым центром Минцифры,
  которого нет в стандартном наборе. Включается через `GIGACHAT_CA_BUNDLE`, см. [src/ru_ner/llm.py](src/ru_ner/llm.py).
- DeepSeek в сравнение не вошёл.
